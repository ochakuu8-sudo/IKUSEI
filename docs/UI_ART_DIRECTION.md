## 1. 現状が見劣りする原因

現行の依頼一覧・成長・選択画面の画像と、素材・CSSを確認した。以下は実装者自身の美術評価。

| 現状の具体的な問題 | 見栄えへの影響 | 必要な変更 |
|---|---|---|
| 人物は髪や衣服の陰影が細かい。背景にも絵画的な陰影がある。一方、枠や紙は単純な線と均一なグラデーションが中心 | 人物・背景・UIが別々に作られたように見える | UIにも光源・厚み・表面の表情を設計。人物に合わせた線の強さと描き込み量で仕上げる |
| 上端の長い紫の枠、左下の大きな状態手帳、3枚の白い依頼がそれぞれ強く主張する | 画面の主役が分散し、キャラクターと依頼の関係が弱い | 背景と補助情報を抑え、顔→3通の依頼→操作へ視線がつながる構図へ作り直す |
| 正面向きの封筒が、室内背景の上に大きく浮いている | 「机上の手紙」という意図と、実際の空間表現が食い違う | 手紙を載せる机面と浅い奥行きを背景側に描き、接地影を共通化する |
| 封筒SVGは210×180・preserveAspectRatio="none"。現在は約267×270へ拡大。ボタンも240×52から380×63へ変形 | 封筒の折り線、角、装飾、線幅まで縦横別々に伸びる | パネル本体と角・縁・封蝋を分離。伸ばす部分を限定し、装飾の比率を固定する |
| 同じ封筒を3枚並べ、色違いの小さな封蝋で区別する | 反復が目立ち、届いた便りを選ぶ情緒が弱い | 共通形状を維持しつつ、差出人の印・筆致を感じる飾り・紙の表情に制御された差を作る |
| 成長は角丸カードと棒グラフ、選択は縦に並ぶ入力フォームに近い | 追加画面だけWebサービスのように見える | 成長を育成帳の記録、選択を物語上の返答として構成。大きな汎用カードの多用をやめる |
| 丸い金枠、手帳の綴じ具、封筒、汎用線画アイコンが、それぞれ違う線と密度を持つ | 紫と金の配色だけが共通で、作品固有の造形が弱い | 紋章・線・角・余白を共通の形から作る。装飾の種類と役割を絞る |

問題は「SVGだから」「CSSだから」ではない。形・素材・光・構図の完成像が決まる前に、機能部品を置いて局所調整を続けたことが原因。描き込んだ素材に交換するだけでも、構図が同じなら改善は限定的。

## 2. 採用する美術方針

**「家格の名残を持つ令嬢の私室で、届いた便りと自身の変化を綴る」**を画面の中心にする。仮の人物・物語にも適用できる美術方針であり、シナリオを確定するものではない。

- 主役は主人公と便り。人物の顔・髪・衣装上半身を一つの大きな形として見せる。
- 室内は静かな絵画的背景。UI周辺の棚・窓枠・装飾の細部を抑え、表示物と線がぶつからないようにする。
- 紙は暖かい象牙色、台帳は葡萄色の革、金は古い金具・家紋・重要な選択に使う。
- 紋章の中心は既存の薔薇を整理した独自図案。日付や通常数値まで金枠で囲わない。
- 華やかさは、大きな立ち絵、文字の組み方、繊細な素材、少数の装飾の精度で作る。すべての部品を豪華にしない。

方向の比較：装飾の強い宮廷調は現在の情報量では枠同士が競合しやすい。現代的な平面カード中心では管理画面の印象が残る。現在の人物・便り・台帳を活かせる上記の方針を採用案とする。

参考として『マリーのアトリエ Remake』の[公式メニュー画面](https://www.koeitecmoamerica.com/manual/S7k4xgKs/en/5100.html)を目視した。日付、所持品、人物の状態がそれぞれ専用の形を持ち、人物札の紙・吊り金具・アイコンがまとまっている点を制作の参考にする。これは私の画面分析であり、作品全体の優劣比較ではない。円形メニューや他作品の装飾・画像は本作へ転用しない。

1200×500を維持。[構図設計図](design/ui-composition.svg)を参照。図は配置と視線の設計であり、完成品質の見本ではない。

| 領域 | 初期の位置・寸法（論理px） | 造形と役割 |
|---|---|---|
| 主人公 | 左側x0〜460。顔の中心は概ねx230・y145 | 腰上までを画面の大きな形として使う。上半身に情報窓を重ねない。背景と接する髪の縁を実寸で仕上げる |
| 日付 | x32・y24付近、幅120 | 小さな暦札。横長の情報帯から独立させる |

| 成長・回想・設定 | 右上x920〜1176 | 同じ意匠の小さな紋章付きメニュー。主操作と同じ大きな板にしない |
| 3通の依頼 | x494・y150から、各210×258、間隔18 | 3件を等価に提示。本文を載せる面は水平に保ち、外形・下敷きで奥行きを作る。中央の依頼を自動的な正解のように強調しない |
| 尊厳と体力 | 左下x28・y372、幅424・高さ100 | 横長の薄い人物記録。三軸の印とランクを横に並べる。現在の縦に大きい状態手帳を置き換える |

寸法は構図案の出発点。文字が入らなければ、同じ構図内の余白・情報配置を調整する。文字サイズから逆算して画面全体を再び巨大な箱で埋めない。ゲームを隠す案内は設けない。

依頼状は、上部に差出人の印と名前、中央に題名、下部に報酬・代償を組む。無意味な中央の空白を余白と呼ばない。題名と報酬の重心を設計し、文字の長さが違っても基準線は揃える。正面の文字面を回転させず、封筒の端や下敷きだけにごく浅い角度差を付ける。

## 4. 最小限、作り直す素材

| 制作物 | 制作内容 | 実装時の組み方 |
|---|---|---|
| UI用の私室背景1点 | 左に人物、右に便りを置く前提で再構成。机面・後景・窓からの光の方向を設計 | 後景、机面、前景を分ける。表示物の接地位置を描き込みに依存させすぎない |
| 紙の部品一式 | 紙面、縁、折り、下敷き、接地影。淡い繊維と端の厚みを作る | 中央だけ伸縮する枠、固定比率の角飾り、独立した影。紙全面の縦横引き伸ばしをしない |
| 革装の台帳一式 | 表紙、小口、背、内側の綴じ、ページ面。大きな見開きとして整合する立体感 | 外装と本文領域を分け、本文の量で背や綴じ具が変形しない構造 |
| 封蝋・家紋 | 共通の封蝋本体と交換できる印面。薔薇の紋章を整理 | 紋章は同じ視点・光・輪郭強度で統一。人物追加は印面の差し替えで対応 |
| 尊厳3種・成長4種の専用印 | 既存の汎用アイコンを、同じ線幅・面の比率・角の処理で再設計 | 数値や名称と分離し、名前や成長式が変わっても絵を交換できる形 |
| 主操作と補助操作の部品 | 選択、決定、ページ移動、タブの通常・選択中・押下・無効 | 枠の形を共通化。選択時は細い金線と局所的な光、無効時も素材感は残す |
| タイトルロゴ | 仮タイトルでも字間・組版・紋章の関係を作品用に作る | 本番名称の差し替えを考慮し、単なる本文フォントの拡大で終えない |

素材は原則2倍寸法で作り、1200×500へ縮小した状態で線と質感を判断する。2倍で作るだけで品質が上がった扱いにしない。AI画像生成を使う場合は背景・紙・革などの素材候補を作り、切り抜き・陰影調整・継ぎ目修正を経て使用。完成UIを1枚絵に焼き込み、文字や条件まで画像にしてはならない。図形として描いた方が精度を出せる枠・印面はSVGで作る。

光は左上から。紙の上辺には薄い明るい縁、右下には柔らかい接地影。金の明るい部分は細く、紙より常時明るい大面積を作らない。革は暗い色に塗るだけでなく、縁の折返しと控えめな表面の変化を持たせる。

## 6. 実現するための制作順序

| 工程 | 作業と成果物 | 次へ進むために解決すること |
|---|---|---|
| 1. 構図ラフ | メイン画面を同じ台本・同じ人物・同じ1200×500で3案作る。違いは人物の占有、依頼の配置、明暗の大きな面 | 320px程度の縮小画像でも人物と便りが主役に見える1案を選ぶ。細かな罫線やボタンの実装はまだ行わない |
| 2. 素材の描き込み | 選んだ構図の紙・革・金・印を、実際の大きさで一部分だけ仕上げる。素材の強さを2案比較 | 人物とUIの描き込み量・輪郭・光が馴染む方を選ぶ。既存の平坦な枠をそのまま正解にしない |
| 3. メイン画面の完成見本 | 通常依頼3件、人物、数値、全操作を含む1枚を仕上げる。納品物は合成画像とレイヤー／寸法情報 | 構図・素材・組版に残った不一致を解決する。この時点でまだ仮の箱なら、全画面の実装へ広げない |
| 4. 部品化と実装 | 見本から素材・位置・文字スタイル・状態表現を抽出し、メイン画面1枚を実装 | 見本と実画面を重ねて、余白・影・切抜き・フォント・装飾の差を詰める。ブラウザー任せの近似で終えない |
| 5. 展開 | 育成帳とADV選択を次の代表画面として仕上げ、その後結果・回想・設定に展開 | 「同じ作品の画面」として素材と造形が連続すること。画面ごとの主役に応じた構図の違いは残す |
| 6. 仕上げ | 選択印、紙の浮き、ページ移動など短い反応を付け、文字の収まりを調整 | 通常・選択中・押下で作品の質感を保つ。実効サイズのために完成像を破壊しない。小画面のプレイを遮断しない |

完成見本はユーザーに毎工程の承認を求めるためのものではない。実装者が比較できる具体的な目標を作り、見本から実画面への劣化を追えるようにするための成果物。画像生成を一回行っただけの画像や、色付きの配置図を完成見本と呼ばない。

ラフや素材案が弱ければ、理由を「主役が分散」「金具だけ光が違う」「紙の輪郭が人物より強い」など画面上の現象で特定し、その箇所を再制作する。弱い案を微調整し続けて工程を消費しない。

## 7. 実装側の変更範囲

- 進行・条件・報酬・保存の処理を再利用し、表示部品を置き換える。新たなゲームパラメータや画面制限は追加しない。
- 現在の複数CSS層による上書きは、画面単位で担当を決めて統合する。見本の座標を再現する場面で、別画面用の古い指定が勝たないようにする。
- 紙・革・印・影・文字のスタイルと、ゲーム状態から表示文を作る処理を分離。物語を書き換えても外観を保てる部品にする。
- 画像・アイコンには表示倍率と切り抜き位置を明記。装飾のアスペクト比は固定する。可変領域は本文面と中央の辺に限定。
- 固有の台本IDに合わせた例外CSSは作らない。代表的な短題名・長題名・複数代償で同じ部品を使う。

## 8. 作業配分と今回の到達点

作業の中心は構図案、素材制作、完成見本、実装との差の修正。ボタン巡回・新しい検証基盤・長い合格表に偏らせない。機能確認は変更した導線の限定試験を一度行い、保存・進行を変えない外観作業で全シナリオを再走しない。

今回の成果物は**原因分析・美術方針・構図設計図・素材制作表・制作工程・実装分担**。新しい完成見本と美術素材は次の制作成果物であり、この設計書だけで見栄えが改善したとは扱わない。
