# UI品質確認記録の書式

この書式を作業ごとの記録へコピーし、空欄を埋める。これは記入用の書式であり、現行ゲームの合格記録ではない。[基準](UI_QUALITY_STANDARD.md)と[改善一覧](UI_QUALITY_IMPLEMENTATION.md)を参照する。

## 小さな外観変更の簡易記録

通常の外観調整は次の3点で十分。以降の詳細表をすべて埋める義務はない。

- 変更画面・変更内容・版：
- 確認した画像とサイズ、V01〜V06で改善した点・残る問題：
- 必要な測定の結果。機能試験を行った場合は変更との関係と結果（外観のみなら「機能変更なし、操作試験なし」）：

詳細な記録は共有基盤の大きな変更や出荷判定に使用する。同じ画像を項目ごとに撮り直さない。

## 完了・公開

- 対象作業の判定：未確認
- ゲーム全体の商業品質判定：未確認（対象だけの合格で置き換えない）
- 今回の公開依頼の有無：
- 公開した場合のソース版・配信用コミット・URL：
- 公開処理、HTML・JS/CSS一致、起動と代表経路の結果：
- 未確認環境・既知の制約・明示指示による例外：

文書だけの変更では、ゲームの配信確認は「対象外：文書のみ」とする。実行していない試験や解消していない残件を合格にしない。
