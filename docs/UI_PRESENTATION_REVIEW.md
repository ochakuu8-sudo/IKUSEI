| 観点 | 今回の改善と目視結果 |
|---|---|

| V04 部品 | 共通GameButtonを依頼・成長関連・結果・回想・設定で使用。用途別の外観とフォーカスを定義。以前の外観CSSから上書き済みの80宣言を整理 |

アルバムは1ページ3件。未解禁の説明と絵の領域を確保し、選択の記録も同じ入口から開く。台帳の人物欄と設定も関連画面として確認・調整した。

## 画像と確認方法

開発サーバーを起動し、`npm run capture:presentation` で再現用データから対象画面へ直接移る。通常のプレイを各画面のために繰り返さない。画像・フォントの読み込み後に撮影する。出力先は既定でリポジトリの隣の `presentation-captures/`。画像は配信用資産へ含めない。

- 1200×500：`title.png`, `desk.png`, `letter.png`, `growth.png`, `dignity.png`, `choice.png`, `result.png`, `archive.png`, `gallery.png` を目視確認。
- 追加：`IKUSEI_VIEWS=normal,settings,journal` による通常依頼・設定・台帳も確認。
- 844×390：`IKUSEI_WIDTH=844`, `IKUSEI_HEIGHT=390`, `IKUSEI_VIEWS=desk,dignity,choice` で撮影。今回の確認画像は `presentation-small/` に保存。縮尺約0.703でもキャンバス内に収まり、主要な題名・条件を読めることを目視確認。
- 390×844：`portrait.png`。キャンバスの外に実寸文字の横向き案内を表示。表示領域が844×352未満の場合も案内する。
- 対象ブラウザー：Playwright付属Chromium。端末サイズは模擬。独立した別評価者による審査ではない。

## 測定・機能確認

`npm run test:presentation` を実行し合格。対象は今回変更した入口と復帰のみ。

- 844×390で尊厳の操作領域が高さ44px以上。尊厳詳細の全説明が本文領域に収まる。
- 尊厳詳細の開閉で本編セーブが変わらない。
- アルバム2ページ目→選択の回想→1件の記録を読み終える→記録一覧→元の2ページ目に復帰。本編セーブは不変。
- 縦向き案内の表示と横向きへの復帰で本編セーブは不変。
- 上記経路に実行時エラーなし。

初回の測定はフォント準備前、回想の確認は記録中の複数場面を考慮していなかったため失敗。確認側の待機・場面終了処理を修正して再実行した。失敗のない経路を繰り返す全ボタン巡回は行っていない。

`npm run build` で型検査・配信用ビルド成功。ゲームロジック未変更のため全依頼の進行試験は再実行していない。既存ADV試験の画面依存の指定は新しい配置へ更新したが、全ADV UI試験は今回は未実行。
